1. Qué es un sistema operativo

1.1 Definición y funciones

Un sistema operativo (SO) es el software que gestiona los recursos del ordenador y ofrece a los programas una forma cómoda y segura de usarlos. Se puede ver de dos maneras complementarias:

  • Como máquina extendida: oculta los detalles del hardware tras abstracciones más fáciles de usar: proceso, fichero, socket o espacio de direcciones.
  • Como gestor de recursos: reparte CPU, memoria, dispositivos y almacenamiento entre los programas y usuarios que compiten por ellos, y evita que se interfieran.

Funciones principales:

  • Gestión de procesos e hilos: crearlos, planificarlos, sincronizarlos y terminarlos.
  • Gestión de la memoria.
  • Gestión de la entrada/salida y de los dispositivos.
  • Gestión de ficheros y del almacenamiento.
  • Protección y seguridad: identificar a los usuarios y controlar sus accesos.
  • Comunicaciones y red.
  • Interfaz con el usuario: intérprete de órdenes (CLI) o interfaz gráfica.
  • Contabilidad y registro del uso de recursos.

Trampa (INAP 2025): la gestión de bases de datos no es una función del sistema operativo. La realiza un sistema gestor de bases de datos, que es una aplicación más (B2-T05).

Componentes:

  • Núcleo (kernel): la parte que está siempre en memoria y se ejecuta en modo privilegiado.
  • Bibliotecas del sistema: ofrecen la interfaz de programación (API) a las aplicaciones.
  • Intérprete de órdenes y entorno gráfico.
  • Utilidades y servicios que funcionan en segundo plano.

1.2 Modo usuario, modo núcleo y llamadas al sistema

El procesador tiene al menos dos modos de funcionamiento:

  • Modo núcleo (kernel, supervisor o privilegiado): puede ejecutar todas las instrucciones, incluidas las privilegiadas (E/S, gestión de memoria, control de interrupciones). En él se ejecuta el núcleo.
  • Modo usuario: solo puede ejecutar instrucciones no privilegiadas. El hardware impide el acceso directo a los dispositivos y a la memoria de otros procesos.

En los procesadores x86 estos modos son anillos de protección: el anillo 0 es el del núcleo y el anillo 3 el de usuario. Los anillos 1 y 2 apenas se usan.

Una llamada al sistema es el mecanismo por el que un programa pide un servicio al núcleo. El programa ejecuta una instrucción especial que cambia a modo núcleo y salta a un punto controlado del SO; al terminar, vuelve a modo usuario. Los programas no suelen invocarlas directamente, sino a través de una API: POSIX en Unix y Linux, y la API Win32 en Windows.

Hay tres formas de entrar en el núcleo:

MecanismoOrigenEjemplo

INAP 2022: los modos de funcionamiento de UNIX son el modo usuario y el modo kernel. «Modo proceso» y «modo microkernel» no existen.

1.3 Arranque

  1. El firmware (BIOS o UEFI) comprueba el hardware y localiza el cargador de arranque. Con Secure Boot, UEFI solo ejecuta cargadores firmados.
  2. El cargador de arranque (GRUB en Linux, Windows Boot Manager en Windows) carga el núcleo en memoria.
  3. El núcleo inicializa la memoria, los dispositivos y el planificador, y crea el primer proceso de usuario: systemd (PID 1) en la mayoría de distribuciones Linux, o smss.exe en Windows, que lanza el resto de procesos del sistema.

1.4 Multiprogramación, multitarea y multiprocesamiento

Son términos que se confunden con facilidad:

  • Multiprogramación: mantener varios programas cargados en memoria para que, cuando uno espera una E/S, la CPU ejecute otro. Su objetivo es no desperdiciar la CPU. Aparece en la tercera generación de ordenadores.
  • Multitarea o tiempo compartido: alternar la CPU entre tareas en intervalos cortos (quantum), de modo que cada usuario o programa parece tener la CPU para sí. Su objetivo es un buen tiempo de respuesta interactivo.
  • Multiprocesamiento: usar varias CPU o núcleos a la vez. Solo aquí hay ejecución realmente simultánea (paralelismo).
  • Multihilo: varios hilos de ejecución dentro de un mismo proceso.

Con una sola CPU, un SO multitarea ofrece concurrencia (las tareas progresan de forma intercalada), pero no paralelismo (ejecución simultánea).

Tiempo real. El resultado solo es correcto si llega a tiempo. En el tiempo real estricto (duro), incumplir un plazo es un fallo del sistema: frenos ABS, aviónica. En el no estricto (blando), solo degrada la calidad: vídeo, voz sobre IP. Ejemplos de sistemas de tiempo real (RTOS): VxWorks, QNX, FreeRTOS y Zephyr.

SO de red frente a SO distribuido:

  • En un SO de red, cada equipo tiene su propio sistema y el usuario sabe que hay varias máquinas: accede a los recursos remotos de forma explícita, como una carpeta compartida o un inicio de sesión remoto.
  • Un SO distribuido presenta un conjunto de equipos como si fuera un único sistema. Sus características son:
    • Concurrencia global: los procesos de todos los nodos se ejecutan a la vez y comparten recursos.
    • Sin reloj común: cada nodo tiene su reloj, y la coordinación se hace mediante mensajes.
    • Fallos independientes: un nodo puede caer sin que caigan los demás, y el sistema debe tolerarlo.
    • Heterogeneidad: nodos con hardware y software distintos.
    • Transparencia: el usuario no ve dónde están los recursos, si están replicados ni si ha habido fallos.

INAP 2024: la característica correcta de un SO distribuido es la concurrencia global. «Reloj común», «homogeneidad» y «dependencia de fallos de los nodos» describen justo lo contrario.

2. Procesos e hilos

Proceso, hilos y estados de ejecución

2.1 Proceso y bloque de control

Un proceso es un programa en ejecución. El programa es un fichero pasivo; el proceso es la actividad, con su estado y sus recursos. Un mismo programa puede dar lugar a varios procesos a la vez.

En memoria, un proceso tiene código, datos, un montículo (heap) para la memoria dinámica y una pila (stack) para las llamadas y las variables locales.

El SO representa cada proceso con un bloque de control de proceso (PCB), que guarda:

  • Identificación: identificador del proceso (PID), del proceso padre (PPID), y usuario y grupo propietarios.
  • Contexto de CPU: contador de programa y registros.
  • Planificación: estado, prioridad y tiempo de CPU consumido.
  • Memoria: tablas de páginas o de segmentos.
  • Recursos: ficheros abiertos y dispositivos asignados.

Creación. En Unix, fork() crea una copia del proceso que la llama, y exec() sustituye su programa por otro. En Windows, CreateProcess() hace ambas cosas en una sola llamada. Los procesos forman una jerarquía padre-hijo.

  • Proceso zombi: ha terminado, pero su padre aún no ha recogido su estado de salida, así que sigue ocupando una entrada en la tabla de procesos.
  • Proceso huérfano: su padre ha terminado antes que él. En Unix lo adopta el proceso init (systemd).

2.2 Estados y transiciones

Un proceso bloqueado nunca pasa directamente a ejecución: primero vuelve a preparado y compite por la CPU.

Estados suspendidos. Si falta memoria, el planificador de medio plazo saca procesos completos a disco (swapping). Aparecen así los estados preparado y suspendido y bloqueado y suspendido. Este mecanismo controla el grado de multiprogramación.

2.3 Hilos

Un hilo (thread) es la unidad que ejecuta la CPU. El proceso es el contenedor de recursos; el hilo, el flujo de ejecución.

Comparten los hilos de un procesoTiene cada hilo
Espacio de direcciones: código, datos y heapContador de programa y registros

  • Ventajas: crear un hilo y cambiar de hilo es más barato que hacerlo con procesos, los hilos comparten datos sin mecanismos de comunicación adicionales y pueden aprovechar varios núcleos.
  • Inconveniente: al compartir memoria, necesitan sincronización (apartado 4).

Hilos de usuario y de núcleo:

  • De usuario (modelo N:1): los gestiona una biblioteca sin que el núcleo los vea. Si uno se bloquea en una E/S, se bloquea todo el proceso, y no pueden usar varias CPU a la vez.
  • De núcleo (modelo 1:1): el SO conoce y planifica cada hilo. Es el modelo de Linux y de Windows.
  • Híbrido (modelo M:N): reparte M hilos de usuario sobre N hilos de núcleo.

Las fibras de Windows son hilos ligeros que planifica la propia aplicación, no el núcleo.

2.4 Cambio de contexto

Para pasar la CPU de un proceso o hilo a otro, el SO guarda el contexto del saliente (registros y contador de programa) y restaura el del entrante. Es tiempo de CPU sin trabajo útil, es decir, sobrecarga. Por eso un quantum demasiado corto empeora el rendimiento. Cambiar entre hilos del mismo proceso es más barato, porque no cambia el espacio de direcciones.

3. Planificación de la CPU

3.1 Niveles de planificación

  • Largo plazo (admisión): decide qué trabajos entran en el sistema y, con ello, el grado de multiprogramación. Es importante en los sistemas por lotes.
  • Medio plazo: suspende y reanuda procesos sacándolos a disco (swapping).
  • Corto plazo (planificador de CPU): elige, entre los procesos preparados, cuál usa la CPU. Se ejecuta con mucha frecuencia.

El despachador (dispatcher) es la parte que realiza el cambio de contexto y entrega la CPU al proceso elegido.

3.2 Planificación apropiativa y no apropiativa

  • No apropiativa (sin expulsión o cooperativa): cuando un proceso obtiene la CPU, la conserva hasta que termina o se bloquea. Es sencilla, pero un proceso con un bucle infinito puede acaparar la CPU y dejar a los demás esperando indefinidamente.
  • Apropiativa (con expulsión, preemptive): el SO puede quitar la CPU al proceso en ejecución. Lo hace normalmente cuando una interrupción del reloj marca el fin de su quantum o cuando llega un proceso de mayor prioridad. Es la que usan los SO de propósito general actuales.

INAP 2022: la planificación no apropiativa es aquella en la que, una vez que a un proceso le toca su turno, no se le puede arrebatar la CPU; por eso un bucle infinito puede aplazar indefinidamente al resto. Las opciones que hablan de un reloj que lanza interrupciones periódicas describen la apropiativa.

Ejemplo resuelto. Llegan a la vez tres procesos: P1 necesita 24 ms de CPU, P2 3 ms y P3 3 ms.

  • FCFS en el orden P1, P2, P3: esperan 0, 24 y 27 ms. Espera media: 17 ms.
  • SJF (P2, P3, P1): esperan 0, 3 y 6 ms. Espera media: 3 ms.

El mismo trabajo, en otro orden, reduce la espera media de 17 a 3 ms. Es el efecto convoy.

3.5 Multiprocesador y tiempo real

  • Multiprocesador. En un sistema simétrico, cada CPU planifica a partir de colas compartidas o propias. La afinidad intenta mantener un proceso en la misma CPU para aprovechar su caché, y el balanceo de carga mueve procesos entre CPU cuando unas están más cargadas que otras.
  • Tiempo real. Se usan algoritmos que garantizan plazos. Rate Monotonic asigna prioridades fijas según la frecuencia de cada tarea. EDF (Earliest Deadline First) da la CPU a la tarea cuyo plazo vence antes.

3.6 Cómo planifican Windows y Linux

Windows planifica hilos, no procesos, de forma apropiativa y con quantum. Usa 32 niveles de prioridad:

  • 16 a 31: tiempo real.
  • 1 a 15: prioridades variables. El sistema las sube temporalmente, por ejemplo cuando termina una espera de E/S.
  • 0: reservado al hilo que pone a cero las páginas libres de memoria.

El kernel de Windows no tiene un hilo central de planificación (INAP 2022). Cuando un hilo se bloquea, agota su quantum o termina, es el propio hilo el que entra en modo núcleo y ejecuta el código del planificador para elegir a quién ceder la CPU. El planificador también se activa con las interrupciones, como la del reloj o la de fin de E/S.

Linux clasifica las tareas en clases de planificación:

  • Normales (SCHED_OTHER y SCHED_BATCH): reparten la CPU en proporción a su valor nice, que va de −20 (más prioridad) a 19. El algoritmo fue CFS (Completely Fair Scheduler, desde 2007) y, desde Linux 6.6 (2023), es EEVDF.
  • Tiempo real:
    • SCHED_FIFO: sin quantum. La tarea sigue hasta que se bloquea o la expulsa otra de mayor prioridad.
    • SCHED_RR: igual, pero con quantum entre tareas de la misma prioridad.
  • Por plazos (SCHED_DEADLINE): basado en EDF.

4. Concurrencia y sincronización

4.1 Condición de carrera y sección crítica

Hay una condición de carrera cuando el resultado depende del orden en que se intercalan procesos o hilos que acceden a datos compartidos. Ejemplo: dos hilos leen un contador que vale 10, ambos le suman 1 y ambos escriben 11. Se ha perdido una actualización.

La sección crítica es el fragmento de código que accede al recurso compartido. Una solución correcta debe garantizar:

  1. Exclusión mutua: solo un proceso a la vez dentro de la sección crítica.
  2. Progreso: si no hay nadie dentro, alguno de los que quieren entrar podrá hacerlo.
  3. Espera limitada: ningún proceso espera indefinidamente para entrar.

  • Lectores-escritores: varios pueden leer a la vez, pero quien escribe necesita acceso exclusivo.
  • Filósofos comensales (Dijkstra): ilustra el interbloqueo y la inanición al competir por recursos compartidos.

4.4 Interbloqueo

Un conjunto de procesos está en interbloqueo (deadlock) cuando cada uno espera un recurso que tiene otro del conjunto y ninguno puede avanzar. Solo ocurre si se dan a la vez las cuatro condiciones de Coffman (1971):

  1. Exclusión mutua: el recurso no se puede compartir.
  2. Retención y espera: un proceso retiene recursos mientras espera otros.
  3. No apropiación: no se puede quitar un recurso a quien lo tiene.
  4. Espera circular: hay un ciclo de procesos que se esperan unos a otros.

  • Interbloqueo: nadie avanza, porque se esperan entre sí.
  • Inanición: un proceso no obtiene nunca el recurso, aunque los demás sí avanzan. Por ejemplo, uno de baja prioridad.
  • Livelock: los procesos cambian continuamente de estado para cederse el paso, pero ninguno progresa.

5. Gestión de memoria

5.1 Objetivos

  • Reubicación: un programa debe poder cargarse en cualquier posición de memoria. Las direcciones lógicas que genera se traducen a direcciones físicas.
  • Protección: un proceso no puede acceder a la memoria de otro ni a la del núcleo.
  • Compartición: varios procesos pueden usar el mismo código, como una biblioteca, de forma controlada.
  • Organización: aprovechar la jerarquía de memoria (B2-T01) y dar a cada proceso una visión cómoda de su espacio.

La MMU (unidad de gestión de memoria) es el hardware que traduce, durante la ejecución, cada dirección lógica o virtual a una dirección física.

5.2 Asignación contigua y fragmentación

Los primeros sistemas asignaban a cada proceso un bloque contiguo de memoria:

  • Particiones fijas: la memoria se divide de antemano. Un proceso pequeño en una partición grande desperdicia el resto: es la fragmentación interna, porque el espacio perdido está dentro de lo asignado.
  • Particiones variables: se asigna a cada proceso exactamente lo que pide. Con el tiempo quedan huecos libres entre procesos, demasiado pequeños para usarlos: es la fragmentación externa. Se corrige con la compactación, que es costosa.

Para elegir un hueco libre:

  • Primer ajuste: el primero en el que cabe. Es rápido.
  • Mejor ajuste: el más pequeño en el que cabe. Deja restos diminutos.
  • Peor ajuste: el más grande.
  • Siguiente ajuste: como el primero, pero buscando desde la última asignación.

5.3 Paginación

La memoria lógica se divide en páginas y la física en marcos del mismo tamaño fijo, normalmente 4 KiB. Las páginas de un proceso pueden estar en marcos no contiguos. Cada dirección lógica se divide en número de página y desplazamiento, y la tabla de páginas de cada proceso indica en qué marco está cada página.

  • Elimina la fragmentación externa. Solo queda fragmentación interna en la última página de cada proceso.
  • TLB: caché de la MMU con las traducciones más recientes. Sin ella, cada acceso a memoria exigiría otro acceso a la tabla de páginas.
  • Tablas multinivel o invertidas: con espacios de direcciones grandes, la tabla se divide en niveles (x86-64 usa cuatro o cinco) o se invierte, con una entrada por cada marco físico.

Cada entrada de la tabla de páginas tiene, además del número de marco, varios bits de control:

BitSignificadoPara qué sirve
Presente o válidoLa página está en memoria físicaSi vale 0, el acceso provoca un fallo de página
Referenciado o de accesoLa página se ha usado recientementeLo usan los algoritmos de reemplazo, como NRU o el reloj
Modificado o sucio (dirty bit)La página se ha escrito desde que se cargóSi se expulsa, hay que escribirla antes en disco. Si está limpia, basta con descartarla
ProtecciónPermisos de lectura, escritura y ejecuciónDetectar accesos no permitidos

INAP 2025: el bit sucio indica que la página se ha modificado y que su contenido difiere de la copia que hay en disco. No indica errores de paridad, ni uso reciente (eso es el bit de referencia), ni permisos (eso son los bits de protección).

5.4 Segmentación

La segmentación divide el programa en unidades lógicas de tamaño variable: código, datos, pila o una biblioteca. Cada dirección es un par formado por el segmento y el desplazamiento, y la tabla de segmentos guarda la base y el límite de cada uno.

  • Ventaja: refleja la estructura del programa, lo que facilita proteger (por ejemplo, el código de solo lectura) y compartir segmentos completos entre procesos.
  • Inconveniente: como los segmentos tienen tamaños distintos, vuelve a aparecer la fragmentación externa.

La segmentación paginada combina ambas técnicas: los segmentos lógicos se dividen en páginas. Los sistemas actuales de 64 bits se basan en la paginación y apenas usan la segmentación del hardware.

5.5 Memoria virtual

La memoria virtual permite ejecutar procesos que no caben enteros en la memoria física: en RAM solo están las partes en uso, y el resto queda en disco, en el área de intercambio. Funciona gracias al principio de localidad: un programa tiende a reutilizar las direcciones que acaba de usar (localidad temporal) y a usar las vecinas (localidad espacial).

Estrategias de carga:

  • Paginación por demanda: una página solo se lleva a RAM cuando se hace referencia a una dirección que está dentro de ella. Es la estrategia habitual.
  • Carga anticipada (prepaginación): se intenta predecir qué páginas se van a necesitar, por ejemplo las adyacentes, y se cargan antes de que se pidan.

INAP 2022: la carga por demanda consiste en que las páginas solo se llevan a RAM si se hizo referencia a una dirección situada en ellas. Las demás opciones de aquella pregunta describen variantes de la carga anticipada.

Fallo de página, paso a paso:

  1. El proceso accede a una página con el bit de presencia a 0 y la MMU genera una excepción.
  2. El SO comprueba que el acceso es válido. Si no lo es, termina el proceso (violación de segmento).
  3. Busca un marco libre o elige una página víctima con el algoritmo de reemplazo. Si la víctima está modificada, la escribe antes en disco.
  4. Lee la página del disco, actualiza la tabla de páginas y repite la instrucción que falló.

Conjunto de trabajo (working set, Denning): las páginas que un proceso ha usado en una ventana de tiempo reciente. Si los conjuntos de trabajo de todos los procesos no caben en memoria, aparece la hiperpaginación (thrashing): el sistema pasa más tiempo trayendo y llevando páginas que ejecutando. La solución es reducir la multiprogramación (suspender procesos) o añadir memoria.

5.7 Intercambio (swapping)

El intercambio saca procesos completos o páginas a disco para liberar memoria. El área de intercambio no es un sistema de ficheros, sino espacio de respaldo de la memoria virtual:

  • Linux: una partición swap o un fichero de intercambio.
  • Windows: el fichero pagefile.sys.

6. Entrada/salida

6.1 Controlador, driver y firmware

  • El controlador de dispositivo (device controller) es hardware: la electrónica que gobierna el dispositivo y ofrece registros de control, de estado y de datos.
  • El driver (manejador o controlador software) es la parte del SO que conoce los detalles de ese hardware y ofrece al resto del sistema una interfaz uniforme. Normalmente se ejecuta en modo núcleo.
  • El firmware es software grabado en el propio dispositivo o en la placa, como la BIOS o UEFI o el firmware de un SSD. Se ejecuta en ese hardware, no dentro del SO.

INAP 2024: cuando una aplicación necesita leer datos de un dispositivo, llama a una función del SO, y el SO llama a una función implementada en el controlador o driver. No es el controlador del bus ni el microkernel.

6.2 Técnicas de E/S

6.3 Software de E/S

El software de E/S se organiza en capas, de abajo arriba:

  1. Manejadores de interrupciones.
  2. Drivers de dispositivo.
  3. Software independiente del dispositivo: nombres uniformes, protección, buffering, tratamiento de errores y asignación de dispositivos.
  4. Software de usuario: bibliotecas de E/S y spooling.

Tipos de dispositivo:

  • De bloque: guardan la información en bloques de tamaño fijo y direccionables, de modo que se puede leer cualquier bloque. Ejemplo: los discos.
  • De carácter: envían o reciben un flujo de bytes sin direccionamiento. Ejemplos: teclado, ratón, terminal o puerto serie.
  • De red: se usan a través de sockets (apartado 4.3).

Técnicas de apoyo:

  • Buffering: guardar datos temporalmente para absorber la diferencia de velocidad entre quien los produce y quien los consume. El búfer puede ser simple, doble o circular.
  • Spooling: volcar en disco los trabajos destinados a un dispositivo que no se puede compartir, como una impresora, y enviárselos de uno en uno.
  • Caché de disco: guardar en memoria los bloques leídos o escritos recientemente.
  • Plug and Play: el SO detecta y configura los dispositivos al conectarlos, sin configuración manual.

6.4 Planificación del disco

En los discos magnéticos, lo más costoso es mover el brazo (tiempo de búsqueda), así que el SO reordena las peticiones:

AlgoritmoCriterio
FCFSPor orden de llegada. Justo pero lento
SSTF (Shortest Seek Time First)La petición más cercana a la posición actual. Rápido, pero puede dejar sin atender las peticiones lejanas (inanición)
SCAN (algoritmo del ascensor)El brazo recorre el disco en un sentido atendiendo peticiones y luego vuelve en el otro
C-SCANComo SCAN, pero solo atiende en un sentido y vuelve al principio sin atender. Los tiempos de espera son más uniformes
LOOK y C-LOOKComo SCAN y C-SCAN, pero el brazo solo llega hasta la última petición pendiente, no hasta el extremo del disco

En los SSD y NVMe no hay brazo, y estos algoritmos pierden sentido: Linux usa planificadores sencillos (mq-deadline) o ninguno. El RAID y el almacenamiento en red se estudian en B4-T05.

7. Sistemas de ficheros

7.1 Ficheros y directorios

Un fichero es una colección de datos con nombre. El sistema guarda además sus metadatos: tamaño, propietario, permisos, fechas y ubicación de sus bloques. Un directorio es una tabla que asocia nombres con ficheros.

  • Estructuras de directorios: de un nivel, de dos niveles (uno por usuario), en árbol, o en grafo acíclico cuando un mismo fichero aparece en varios directorios gracias a los enlaces.
  • Rutas: absolutas, desde la raíz, o relativas, desde el directorio actual.
  • Montaje: en Unix y Linux hay un único árbol que nace en /, y cada volumen se monta en un directorio de ese árbol. En Windows, cada volumen tiene su letra de unidad (C:, D:) con su propio árbol, aunque también admite puntos de montaje.

El espacio libre se controla con mapas de bits (un bit por bloque) o con listas de bloques libres.

7.3 Enlaces

  • Enlace duro: otra entrada de directorio que apunta al mismo i-nodo. El fichero solo se borra cuando desaparece su último enlace. No puede cruzar sistemas de ficheros ni, normalmente, apuntar a directorios.
  • Enlace simbólico: un fichero especial que contiene la ruta de otro. Puede cruzar sistemas de ficheros y apuntar a directorios, pero queda roto si se borra el destino.

En Unix se crean con ln y ln -s. NTFS también admite enlaces duros, enlaces simbólicos y uniones (junctions).

7.4 Consistencia

Un corte de luz a mitad de una escritura puede dejar inconsistentes las estructuras del sistema de ficheros. Hay tres soluciones:

  • Comprobación tras el fallo: fsck en Unix y chkdsk en Windows recorren todo el volumen. Es lento en discos grandes.
  • Journaling (registro por diario): antes de modificar las estructuras, se anota la operación en un diario. Tras un fallo, basta con completar o descartar las operaciones pendientes. Puede proteger solo los metadatos, que es lo habitual, o también los datos. Lo usan NTFS, ext3, ext4 y XFS.
  • Copia en escritura (copy-on-write): nunca se sobrescribe un bloque en uso. El nuevo contenido se escribe en otro sitio y después se cambia el puntero. Permite hacer instantáneas (snapshots) casi sin coste. Lo usan ZFS, Btrfs, APFS y ReFS.

8. Protección y seguridad del sistema operativo

El SO es la base de la seguridad del equipo: si se compromete el núcleo, se compromete todo lo que se ejecuta encima.

  • Identificación y autenticación: cada usuario tiene una identidad (UID en Unix, SID en Windows) y debe demostrarla con una contraseña, un certificado o biometría.
  • Control de acceso:
    • Discrecional (DAC): el propietario decide quién accede. Es el modelo de los permisos Unix y de las ACL de NTFS.
    • Obligatorio (MAC): el sistema impone una política que el usuario no puede cambiar. Ejemplos: SELinux (Red Hat, Android), AppArmor (Ubuntu, SUSE) y los niveles de integridad de Windows.
    • Basado en roles (RBAC): los permisos se asignan a roles, y los usuarios reciben roles.
  • Matriz de acceso: sus filas son los sujetos y sus columnas los objetos. Se implementa por columnas, como listas de control de acceso (ACL, asociadas a cada objeto), o por filas, como capacidades (asociadas a cada sujeto).
  • Mínimo privilegio: cada usuario y cada proceso, con los permisos justos. Las cuentas de administración se separan de las de uso diario.
  • Mitigaciones del sistema:
    • Aleatorización del espacio de direcciones (ASLR).
    • Memoria de datos no ejecutable (DEP o NX).
    • Arranque seguro (Secure Boot) con apoyo del TPM.
    • Cifrado de disco: BitLocker, LUKS o FileVault.
    • Aislamiento de aplicaciones (sandbox).
  • Auditoría: registro de los sucesos de seguridad.

La ciberseguridad en general se estudia en B2-T13.

9. Windows

9.1 Familias y ediciones

  • La familia MS-DOS y Windows 9x (hasta Windows Me) era monousuario y no tenía una protección real de la memoria.
  • La familia Windows NT (desde NT 3.1, en 1993) se diseñó desde cero como un sistema multiusuario, apropiativo, portable y seguro. Todas las versiones actuales derivan de ella: Windows 10, Windows 11 y Windows Server.

Ediciones de escritorio: Home, Pro, Enterprise y Education, además de las variantes IoT y LTSC (Long-Term Servicing Channel). LTSC no recibe actualizaciones de funciones durante años y se usa en equipos que no deben cambiar, como los de control industrial o los sanitarios.

Ediciones de servidor:

  • Standard.
  • Datacenter: con derecho a máquinas virtuales ilimitadas y funciones de almacenamiento y red definidos por software.
  • Essentials, para organizaciones pequeñas, y Datacenter: Azure Edition.

Opciones de instalación del servidor:

  • Server Core: sin interfaz gráfica local. Tiene menos superficie de ataque y necesita menos parches. Se administra en remoto.
  • Experiencia de escritorio: con la interfaz gráfica completa.
  • Nano Server, presentado en 2016, hoy solo existe como imagen base para contenedores.

Hitos con fecha:

  • Windows 11 (2021) exige TPM 2.0, UEFI con arranque seguro y un procesador de 64 bits compatible.
  • El soporte de Windows 10 terminó el 14/10/2025. Desde entonces solo recibe parches mediante el programa de actualizaciones de seguridad extendidas (ESU).
  • Windows 11 recibe una actualización de funciones al año. Cada versión tiene 24 meses de soporte en Home y Pro, y 36 en Enterprise y Education.
  • Windows Server 2025 está disponible desde noviembre de 2024. Windows Server 2012 y 2012 R2 están fuera de soporte desde octubre de 2023.

9.2 Arquitectura

Windows NT tiene un núcleo híbrido con dos niveles.

Modo usuario:

  • Aplicaciones y subsistemas de entorno, que ofrecen una API a las aplicaciones. NT nació con tres subsistemas: Win32, POSIX y OS/2. Hoy solo queda Win32.
  • WSL (Subsistema de Windows para Linux) permite ejecutar programas de Linux. WSL 2 usa un kernel Linux real dentro de una máquina virtual ligera.
  • ntdll.dll: la puerta de entrada a las llamadas al sistema.
  • Procesos del sistema y servicios.

Modo núcleo. El fichero ntoskrnl.exe contiene el ejecutivo y el kernel:

ComponenteFunción

KernelFunciones de bajo nivel: planificación de hilos, interrupciones y excepciones, y sincronización entre procesadores
DriversDe dispositivos, de sistemas de ficheros y de red. Se cargan de forma dinámica y se ejecutan en modo núcleo, salvo los del marco UMDF, que funcionan en modo usuario

Por qué es híbrido y no microkernel. La capa del kernel se diseñó con ideas de microkernel, y algunos textos la llaman así. Pero el ejecutivo, los drivers y el subsistema gráfico también se ejecutan en modo núcleo, en el mismo espacio de direcciones. En un microkernel serían procesos en modo usuario.

WOW64 (Windows on Windows 64) permite ejecutar aplicaciones de 32 bits en Windows de 64 bits. Windows de 64 bits no ejecuta aplicaciones de 16 bits.

9.4 El registro

El registro es la base de datos jerárquica que guarda la configuración del sistema, del hardware, de las aplicaciones y de los usuarios.

  • Se organiza en claves, que son como carpetas y pueden tener subclaves, y valores, que son pares de nombre y dato con un tipo.
  • Físicamente se guarda en ficheros llamados colmenas (hives), en %SystemRoot%\System32\config, y en el fichero NTUSER.DAT de cada perfil de usuario.
  • Se edita con regedit o con PowerShell, y de forma centralizada con directivas de grupo.

Claves raíz:

  • HKEY_LOCAL_MACHINE (HKLM): configuración del equipo.
  • HKEY_CURRENT_USER (HKCU): configuración del usuario que ha iniciado sesión.
  • HKEY_USERS (HKU): todos los perfiles de usuario cargados.
  • HKEY_CLASSES_ROOT (HKCR): asociaciones de ficheros y clases COM.
  • HKEY_CURRENT_CONFIG (HKCC): perfil de hardware actual.

En Unix no hay registro: la configuración se guarda en ficheros de texto, sobre todo en /etc.

10. Unix y Linux

10.1 Historia y familias

  • Unix nace en 1969 en los Laboratorios Bell de AT&T, obra de Ken Thompson y Dennis Ritchie, tras el abandono del proyecto MULTICS. En 1973 se reescribe en C, lo que lo hace portable.
  • Se divide en dos grandes ramas: System V, de AT&T, y BSD, de la Universidad de California en Berkeley. De ellas derivan los Unix comerciales (AIX de IBM, HP-UX de HP y Solaris de Sun, hoy de Oracle) y los BSD libres (FreeBSD, OpenBSD y NetBSD).
  • POSIX (Portable Operating System Interface, IEEE 1003, también ISO/IEC 9945) estandariza la interfaz de los sistemas de tipo Unix: llamadas al sistema, shell y utilidades. Un programa que solo usa POSIX se puede compilar en cualquier sistema conforme. La versión vigente es POSIX.1-2024.
  • La marca UNIX pertenece a The Open Group, que certifica los sistemas conformes con la Single UNIX Specification. macOS es un UNIX certificado. Linux, en general, no lo es, aunque en la práctica es compatible.
  • GNU (GNU's Not Unix) es el proyecto que Richard Stallman anunció en 1983 para crear un sistema de tipo Unix libre. Aportó el compilador GCC, la biblioteca glibc, la shell bash, las utilidades básicas y la licencia GPL (B2-T14).
  • Linux es el núcleo que creó Linus Torvalds en 1991. Se inspiró en Unix y lo desarrolló sobre MINIX, el sistema docente de Andrew Tanenbaum (1987), pero no contiene código de MINIX. Se distribuye con licencia GPLv2. Al sistema completo, núcleo Linux más herramientas GNU, se le llama GNU/Linux.
  • Debate Tanenbaum-Torvalds (1992): Tanenbaum criticó que Linux fuera monolítico, un diseño que consideraba obsoleto frente al microkernel de MINIX.

10.3 Arquitectura y filosofía

  • Núcleo monolítico y modular: los drivers se cargan como módulos (lsmod, modprobe) sin reiniciar. Está escrito en C y, desde Linux 6.1 (2022), admite componentes en Rust.
  • Todo es un fichero: los dispositivos (/dev), la información del núcleo (/proc, /sys) y las tuberías se manejan con las mismas llamadas: abrir, leer, escribir y cerrar.
  • Herramientas pequeñas que se combinan: cada orden hace una sola cosa, y las órdenes se encadenan con tuberías.
  • Descriptores estándar: 0 es la entrada estándar (stdin), 1 la salida estándar (stdout) y 2 la salida de errores (stderr). Se redirigen con > (sobrescribe), >> (añade), < (entrada) y 2> (errores).
  • Interfaz gráfica separada del núcleo: X Window System (nacido en el MIT en 1984; su versión vigente es X11 y su implementación habitual, X.Org) y su sucesor, Wayland. Sobre ellos funcionan los entornos de escritorio: GNOME, KDE Plasma, Xfce y otros.

10.4 Procesos y señales

  • Cada proceso tiene un PID, un PPID y usuario y grupo reales (quien lo lanzó) y efectivos (con cuyos permisos actúa).
  • Se crean con fork() y exec(). El primer proceso, init (hoy normalmente systemd, con PID 1), es el antepasado de todos y adopta a los huérfanos.
  • Los daemons son procesos de servicio que se ejecutan en segundo plano, sin terminal asociado. Por convención, su nombre suele acabar en d, como sshd o httpd.
  • Herramientas: ps y top para ver procesos, kill para enviar señales, nice y renice para la prioridad, y jobs, fg y bg para los trabajos en segundo plano.

10.6 Usuarios y permisos

  • Las cuentas se definen en /etc/passwd (nombre, UID, GID, directorio personal y shell). Los resúmenes (hashes) de las contraseñas están en /etc/shadow, que solo puede leer root. Los grupos, en /etc/group.
  • Solo el UID 0 (root) tiene privilegios especiales. Los UID bajos se reservan por convención a cuentas de sistema y de servicios (por ejemplo, por debajo de 1000 en muchas distribuciones), pero eso no les da ningún privilegio.
  • sudo permite a usuarios autorizados ejecutar órdenes concretas como otro usuario, normalmente root, según la política de /etc/sudoers (que se edita con visudo), y deja registro de ello. su cambia de usuario y pide la contraseña del usuario de destino.

Permisos básicos. Cada fichero tiene un propietario y un grupo, y tres juegos de permisos: propietario (u), grupo (g) y otros (o). Cada juego combina lectura (r = 4), escritura (w = 2) y ejecución (x = 1).

10.7 Administración

  • Shells: sh (Bourne), csh (C shell, de BSD), ksh (Korn), bash (Bourne-Again SHell, la habitual en Linux) y zsh (la predeterminada en macOS desde Catalina, 2019). La shell no forma parte del núcleo: es un programa más.
  • systemd gestiona el arranque y los servicios mediante unidades con dependencias: .service, .socket, .timer, .mount y .target. Se maneja con systemctl (start, stop, enable, status). Sus targets sustituyen a los niveles de ejecución (runlevels) del antiguo SysV init: multi-user.target equivale al nivel 3 y graphical.target al 5.
  • Registros: journald (journalctl) y los ficheros de /var/log, con rsyslog para centralizarlos.
  • Tareas programadas: cron (crontab) o temporizadores de systemd.
  • Paquetes y actualizaciones: apt o dnf, contra repositorios firmados.
  • Almacenamiento: mount para montar volúmenes, /etc/fstab para montarlos al arrancar y LVM para gestionar volúmenes lógicos.
  • Red: ip y ss.
  • Administración remota: SSH, preferiblemente con claves y sin acceso directo de root.
  • Automatización: scripts de shell y herramientas de gestión de la configuración como Ansible o Puppet.
  • Contenedores: se apoyan en dos mecanismos del núcleo Linux: los namespaces, que aíslan lo que ve cada proceso, y los cgroups, que limitan lo que consume. Se estudian en B2-T07.

11. Otros sistemas operativos

11.1 macOS

  • Origen: sustituye al Mac OS clásico (1984–2001), con el que no comparte arquitectura. Deriva de NeXTSTEP, el sistema de NeXT, que Apple compró en 1997, y nace como Mac OS X en 2001.
  • Base: Darwin, de código abierto, con el núcleo XNU. Es híbrido: combina el microkernel Mach (de Carnegie Mellon) con componentes de FreeBSD y el marco de drivers I/O Kit. Darwin es también la base de iOS, iPadOS, watchOS y tvOS.
  • Rasgos: es un UNIX certificado, su interfaz gráfica es Aqua y su sistema de ficheros es APFS (antes, HFS+).
  • Plataformas: usó procesadores Intel hasta la transición a Apple silicon (ARM64), iniciada en 2020 con macOS 11. Rosetta 2 traduce las aplicaciones de Intel. Apple ha anunciado que macOS 26 (2025) es la última versión para Mac con Intel.
  • Seguridad:
    • Gatekeeper y notarización: solo se ejecuta software firmado y revisado por Apple, salvo que el usuario lo autorice.
    • SIP (protección de la integridad del sistema): impide modificar los ficheros del sistema incluso a root.
    • FileVault: cifrado del disco.
    • XProtect: protección contra malware.
  • Gestión corporativa: mediante MDM (B4-T15).

11.2 z/OS y los sistemas del mainframe

z/OS es el sistema operativo principal de los mainframes de IBM, de arquitectura z y 64 bits. Su linaje es OS/360 (1964), MVT, MVS (1974), OS/390 (1995) y, desde 2000, z/OS.

Características:

  • Fiabilidad, disponibilidad y facilidad de servicio (RAS): hardware y software con autocomprobación, recuperación automática y cambios en caliente.
  • Parallel Sysplex: agrupa varios sistemas z/OS que comparten datos y funcionan como uno solo, para lograr disponibilidad continua.
  • Workload Manager (WLM): reparte los recursos según los objetivos de servicio que define la organización.
  • Compatibilidad hacia atrás: ejecuta sin cambios aplicaciones escritas hace décadas.
  • Cargas típicas: procesamiento masivo por lotes (batch) y transacciones en línea (OLTP) con monitores como CICS e IMS.

12. Sistemas operativos para dispositivos móviles

12.1 Qué los diferencia

  • Hardware: un SoC que integra CPU ARM, GPU, NPU y módem (B2-T01).
  • Energía: el SO limita de forma agresiva lo que hacen las aplicaciones en segundo plano y puede cerrarlas para liberar memoria.
  • Seguridad por diseño:
    • Cada aplicación se ejecuta aislada en su propio espacio (sandbox).
    • Necesita permisos explícitos para usar la cámara, la ubicación o los contactos.
    • Debe estar firmada y suele distribuirse a través de una tienda que la revisa.
  • Seguridad respaldada por hardware: cifrado del almacenamiento, arranque verificado y un entorno aislado para claves y biometría (Secure Enclave en Apple; TEE y StrongBox en Android).
  • Actualizaciones por red (OTA), con un periodo de soporte limitado que conviene exigir al comprar dispositivos.
  • Interfaz táctil y sensores: acelerómetro, GPS, biometría.

Android domina en número de dispositivos en el mundo e iOS ocupa casi todo el resto. Las cifras exactas cambian cada año y no son materia de examen.

12.2 Android

  • Lo desarrolla Google, que compró Android Inc. en 2005, y se presentó en 2007 junto con la Open Handset Alliance.
  • El código base es el AOSP (Android Open Source Project), con licencia Apache 2.0. El núcleo Linux mantiene su licencia GPLv2. Los servicios de Google, como Google Play, son propietarios y se licencian aparte a los fabricantes.

Entorno de ejecución:

  • Las aplicaciones se escriben en Kotlin (el lenguaje preferente) o Java y se compilan a bytecode DEX. También pueden incluir código nativo en C/C++ mediante el NDK.
  • Dalvik, la máquina virtual original, compilaba durante la ejecución (JIT) desde Android 2.2.
  • ART la sustituyó: fue opcional en Android 4.4 y la única opción desde 5.0. Al principio compilaba de antemano (AOT) durante la instalación. Desde Android 7 combina JIT y AOT guiada por perfiles de uso, para equilibrar una instalación rápida con un buen rendimiento.

Componentes de una aplicación:

  • Actividad: una pantalla con interfaz de usuario.
  • Servicio: trabajo en segundo plano, sin interfaz.
  • Receptor de emisiones (broadcast receiver): reacciona a eventos del sistema o de otras aplicaciones, como la batería baja.
  • Proveedor de contenidos: comparte datos con otras aplicaciones, como los contactos.

Los componentes se activan mediante mensajes llamados intents. El fichero AndroidManifest.xml declara los componentes, los permisos que necesita la aplicación y las versiones y el hardware con los que es compatible.

Ciclo de vida de una actividad: onCreate → onStart → onResume (visible y en primer plano) → onPause (pierde el foco) → onStop (deja de ser visible) → onDestroy. Desde onStop puede volver a primer plano con onRestart, onStart y onResume.

  • onDestroy se llama cuando la actividad termina o cuando el sistema la destruye temporalmente, por ejemplo al girar la pantalla.
  • Si el sistema necesita memoria, puede matar el proceso sin llamar a onDestroy.

Seguridad:

  • Cada aplicación recibe su propio UID de Linux, de modo que es el núcleo el que impone el aislamiento entre aplicaciones.
  • SELinux funciona en modo obligatorio desde Android 5.0.
  • Desde Android 6.0, los permisos peligrosos se conceden en tiempo de ejecución, cuando la aplicación los necesita, y no al instalarla.
  • Arranque verificado (Verified Boot) y cifrado basado en ficheros.
  • Google Play Protect analiza las aplicaciones.
  • El perfil de trabajo de Android Enterprise separa los datos personales de los corporativos.

Formatos:

  • APK (Android Package): un fichero ZIP firmado. Es lo que se instala en el dispositivo.
  • AAB (Android App Bundle): el formato de publicación. Google Play lo exige a las aplicaciones nuevas desde agosto de 2021 y genera a partir de él los APK adecuados para cada dispositivo.

Fragmentación y actualizaciones. Cada fabricante adapta Android y decide durante cuánto tiempo actualiza sus dispositivos. Para acelerar las actualizaciones:

  • Project Treble (Android 8.0) separó el código del fabricante del resto del sistema.
  • Project Mainline (Android 10) permite actualizar componentes del sistema a través de Google Play.

12.3 iOS y iPadOS

  • Es el sistema de Apple para el iPhone (2007, al principio llamado iPhone OS). iPadOS se separó de iOS en 2019.
  • Comparte con macOS el núcleo XNU y la base Darwin, así que es un sistema de tipo Unix. Es propietario y solo funciona en hardware de Apple.

  • COPE (Corporate-Owned, Personally Enabled): dispositivo corporativo con uso personal permitido.
  • COBO (Corporate-Owned, Business Only): dispositivo corporativo solo para uso profesional.

Gestión. Las soluciones MDM, MAM, EMM y UEM se estudian en B4-T15. Desde el punto de vista del SO, lo esencial es que el perfil de trabajo de Android Enterprise y la inscripción de usuario de Apple separan los datos personales de los corporativos, y permiten borrar solo los corporativos.

Marco público:

  • Accesibilidad: el Real Decreto 1112/2018 obliga a que las aplicaciones móviles del sector público sean accesibles desde el 23 de junio de 2021.
  • ENS: el Esquema Nacional de Seguridad (Real Decreto 311/2022) exige proteger los dispositivos portátiles de la organización (medida mp.eq.3). El CCN publica guías CCN-STIC de configuración segura para Android e iOS.

13. Administración y operación

El ciclo de vida de un sistema operativo en una organización tiene estas fases:

  1. Selección: compatibilidad con las aplicaciones, soporte del fabricante y fecha de fin de soporte, licencias, competencias del equipo e integración con la identidad corporativa.
  2. Despliegue: imagen maestra e instalación desatendida, para que todos los equipos queden iguales. En Windows, Sysprep con fichero de respuestas o Autopilot. En Linux, Kickstart (Red Hat), preseed (Debian) o cloud-init (en la nube).
  3. Bastionado (hardening): eliminar servicios y software innecesarios, ajustar permisos y aplicar una configuración de referencia, como las guías CCN-STIC o los benchmarks del CIS. En el ENS lo exige la medida op.exp.2 (configuración de seguridad).
  4. Parches: aplicarlos con un procedimiento de prueba y un despliegue escalonado (op.exp.4, mantenimiento y actualizaciones de seguridad). No deben usarse sistemas fuera de soporte.
  5. Cuentas y privilegios: cuentas nominativas, cuentas de administración separadas, mínimo privilegio, sudo o UAC, y contraseñas locales distintas en cada equipo (LAPS).
  6. Registro y monitorización: centralizar los registros (Visor de eventos, journald o syslog) en un SIEM (op.exp.8, registro de la actividad) y vigilar CPU, memoria, disco y servicios.
  7. Copias de seguridad y recuperación, probadas periódicamente.
  8. Automatización: PowerShell, scripts de shell y Ansible, con la configuración versionada (infraestructura como código).
  9. Retirada: borrado seguro de los datos y baja en el inventario.

15. Aplicación al supuesto práctico

En un supuesto, el sistema operativo aparece al elegir la plataforma de un servicio, al definir el puesto de trabajo o al diseñar la gestión de los móviles. Conviene:

  • Justificar la plataforma por requisitos, no por preferencia: compatibilidad de las aplicaciones, soporte y fin de vida, licencias, competencias del equipo, integración con la identidad (Active Directory, Entra ID o LDAP) y coste de todo el ciclo de vida.
  • Evitar sistemas fuera de soporte. Si una aplicación heredada lo exige, aislarla (segmentación de red, virtualización) y planificar su migración. Ejemplo: los puestos que siguen con Windows 10 después de octubre de 2025.
  • Describir el bastionado y la operación con las medidas del ENS: configuración de seguridad (op.exp.2), mantenimiento y actualizaciones (op.exp.4), protección frente a código dañino (op.exp.6) y registro de la actividad (op.exp.8).
  • En servidores: instalación mínima (Server Core o una instalación mínima de Linux), administración remota segura, alta disponibilidad con clúster o varias instancias, y copias de seguridad probadas.
  • En puestos de trabajo: imagen corporativa, gestión centralizada (GPO o Intune), cifrado de disco, EDR y actualizaciones automáticas.
  • En móviles: modelo de propiedad (BYOD o corporativo), MDM o UEM, separación de los datos de trabajo y aplicaciones accesibles conforme al RD 1112/2018.
  • Pensar en la salida: usar formatos y estándares abiertos (POSIX, protocolos estándar) para no quedar atado a una plataforma.

Resumen de repaso

Núcleo de estudio

  • Qué es un SO: gestiona los recursos (CPU, memoria, E/S y ficheros) y ofrece abstracciones a los programas. Funciona en dos modos, núcleo y usuario, y los programas le piden servicios mediante llamadas al sistema.
  • Procesos e hilos: un proceso es un programa en ejecución, descrito por su PCB. El hilo es la unidad que se planifica; los hilos de un proceso comparten su memoria y sus recursos.
  • Estados: nuevo, preparado, ejecución, bloqueado y terminado, más los suspendidos cuando el proceso se saca a disco.
  • Planificación: apropiativa (por quantum o por prioridad) o no apropiativa. Algoritmos: FCFS, SJF, SRTF, prioridades, Round Robin, HRN y colas multinivel.
  • Concurrencia: la sección crítica se protege con mutex, semáforos o monitores. El interbloqueo exige las cuatro condiciones de Coffman y se previene, se evita (algoritmo del banquero), se detecta o se ignora.
  • Memoria: la paginación usa marcos fijos y no tiene fragmentación externa; la segmentación usa unidades lógicas y sí la tiene. La memoria virtual carga páginas por demanda. El bit sucio obliga a escribir la página antes de expulsarla. El exceso de fallos de página es la hiperpaginación.
  • E/S: el driver es software del SO; el controlador es hardware; el firmware se ejecuta en el propio dispositivo. Técnicas: sondeo, interrupciones y DMA.
  • Ficheros: asignación contigua, enlazada (FAT) o indexada (i-nodo, MFT). La consistencia se protege con journaling o con copia en escritura.
  • Estructuras del núcleo: monolítica (Linux, modular), por capas, microkernel (servicios como procesos servidores), híbrida (Windows NT, XNU) y máquina virtual.
  • Windows: familia NT y núcleo híbrido (ejecutivo, kernel, drivers y HAL). Planifica hilos con 32 prioridades. Registro, SID, tokens y ACL. PowerShell, Active Directory y GPO.
  • Unix y Linux: Unix nace en 1969 y se divide en System V y BSD; POSIX estandariza su interfaz. Linux es el núcleo y las distribuciones lo completan. Todo es un fichero; permisos rwx con setuid, setgid y sticky; sudo y systemd.
  • Otros: macOS (Darwin y XNU, UNIX certificado) y z/OS (mainframe de IBM: batch y OLTP, JCL, RACF, Parallel Sysplex, LPAR y z/VM).
  • Móviles: Android (núcleo Linux, HAL, ART, componentes y un UID por aplicación) e iOS (XNU; capas Cocoa Touch, Media, Core Services y Core OS; firma obligatoria y Secure Enclave).

Claves de test

  • Un proceso no es un programa ni un hilo. Los hilos comparten memoria, pero cada uno tiene su pila y sus registros.
  • Un proceso bloqueado pasa a preparado, nunca directamente a ejecución.
  • Concurrencia es intercalado; paralelismo es simultaneidad real con varias CPU.
  • La multiprogramación busca aprovechar la CPU; el tiempo compartido busca un buen tiempo de respuesta.
  • En la planificación no apropiativa, el proceso conserva la CPU hasta que termina o se bloquea.
  • Round Robin = cola circular + quantum. SJF minimiza la espera media. HRN elige por (espera + servicio) / servicio.
  • Inanición no es interbloqueo. El algoritmo del banquero es evitación, no prevención.
  • Fragmentación interna: paginación y particiones fijas. Fragmentación externa: segmentación y particiones variables.
  • Bit sucio: página modificada. Bit de referencia: página usada recientemente. Bit de presencia: página en RAM.
  • FIFO sufre la anomalía de Belady. El algoritmo óptimo no se puede implementar.
  • Algoritmos de reemplazo de páginas: óptimo, FIFO, segunda oportunidad/reloj, NRU, LRU, NFU y LFU. YaST y YAFFS no lo son.
  • Con DMA, la CPU solo interviene al principio y al final de la transferencia.
  • El nombre del fichero no está en el i-nodo. Un enlace duro no cruza sistemas de ficheros.
  • FAT32 admite ficheros de 4 GiB como máximo. NTFS va por la versión 3.1. ReiserFS ya no está en Linux.
  • Linux es monolítico y modular, no microkernel. Windows NT y XNU son híbridos.
  • El kernel de Windows no tiene un hilo central de planificación.
  • POSIX significa Portable Operating System Interface (IEEE 1003).
  • Solo el UID 0 tiene privilegios especiales. El directorio de los usuarios es /home, no /usr. La configuración del sistema está en /etc.
  • chmod 755 = rwxr-xr-x y 644 = rw-r--r--. setuid = 4000, setgid = 2000 y sticky = 1000.
  • SIGKILL (9) no se puede capturar; SIGTERM (15) es la terminación ordenada y la que envía kill por defecto.
  • Las versiones de Linux se llaman distribuciones. Active Directory no es el sistema operativo, sino un rol de Windows Server.
  • Gestionar bases de datos no es una función del SO.
  • En Android, el APK se instala y el AAB se publica. ART sustituyó a Dalvik en Android 5.0.
  • El jailbreak rompe la seguridad de iOS; no sirve para instalar iOS en otro hardware.
